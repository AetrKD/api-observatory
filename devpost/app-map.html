API Observatory 구현 안내 지도

GitHub 저장소에서 API 호출과 코드 위치를 찾고, 선택적으로 배포 주소를 입력해 실제 GET 응답을 확인하는 도구입니다. GitHub는 소스를 제공하고, Turso는 계정별 설정·분석 결과를 보관합니다. 저장소 코드를 실행하지 않습니다.

한 번의 사용자 동작이 결과가 되기까지

① 배포 주소 저장→② 권한·대상 검증 후 GET 요청→③ 목록·상세에 결과 표시

아래는 실제 코드에 근거한 참고 경로입니다. 사용자와 함께 코드 탐색을 완료했다는 기록은 아닙니다. 경로는 API_Test_Service 폴더 기준입니다.

1. 입력과 출력: 화면

src/components/project-probe-panel.tsx에서 ProjectProbePanel과 save를 찾으세요. 저장 요청 뒤 조건이 갖춰지면 응답 조회를 시작합니다. LiveApiResult는 HTTP 코드·응답 시간·미리보기를 보여줍니다.

2. 실행과 보관: 서버

src/lib/checks/project-service.ts의 saveProjectProfile과 runProjectProbe가 계정·저장소 접근을 검증하고, 설정 저장·중복 실행 제한·캐시·실제 요청을 처리합니다. 설정과 결과 요약은 Turso에 저장하지만 응답 본문은 저장하지 않습니다.

화면과 서버를 연결하는 입구는 src/app/api/repositories/[id]/project-checks/route.ts의 PUT과 POST입니다.

3. 조회 범위: 실행 계획

src/lib/checks/project-plan.ts의 planProjectRequests는 상대 주소에 배포 도메인을 결합하고, 같은 도메인의 GET만 최대 20개 주소로 묶습니다. 다른 도메인·POST·WebSocket·미해결 주소는 제외 이유를 남깁니다.

tests/project-plan.test.ts에서 같은 주소의 중복 제거와 다른 도메인·비GET 제외를 검증합니다. tests/project-probe.integration.test.ts는 설정 격리·암호화·캐시·본문 미보관 등을 검증합니다.

바꾸려는 내용별 출발점

  • 상단 입력과 결과 표시: src/components/project-probe-panel.tsx
  • 자동 조회 대상과 한도: src/lib/checks/project-plan.ts 및 대응 테스트
  • 공개 HTTPS·사설 주소 차단: src/lib/checks/policy.ts
  • 일일 예약 실행: src/app/api/cron/checks/route.ts와 vercel.json. 프로젝트 자동 조회 설정과 개별 등록 점검의 일일 예약은 별도입니다.

다음 프로젝트에 재사용할 계획 작성법

“자동으로 결과를 보여준다”를 입력 → 대상 선택 규칙 → 표시 결과 → 실패·제외 이유 → 검증으로 나누세요. 이번 구현에서는 “같은 도메인의 GET만 조회”라는 기준이 요구사항, 요청 계획, 테스트로 이어졌습니다.

근거: devpost/prd.md의 Project-Level Automatic Responses, devpost/spec.md의 Project Profiles and Batch Response Checks, 위의 구현과 테스트. 저장소 분석 결과와 실제 응답을 구분하면, 코드만 읽고 정상 작동한다고 판단하는 오류를 피할 수 있습니다.

응답 형식과 공개 소스 읽기 개선

src/components/response-format-select.tsx는 공통·개별 점검에서 같은 응답 형식을 선택하게 합니다. src/lib/checks/accept.ts가 허용된 Accept 값을 만들고, scripts/migrate.ts가 기존 DB에 설정 열을 추가합니다. JSON을 요청해도 서버가 반환한 실제 형식과 조건을 확인해야 합니다.

src/lib/github.ts는 공개 소스를 커밋 고정 원문으로 읽어 파일별 REST 호출을 줄입니다. tests/github.test.ts에서 원문 요청의 인증 제외·커밋 고정·비공개 API 경로·인코딩을 검증합니다. 실제 공개 예제 103개 파일 분석과 JSON HTTP 200 조회를 확인했습니다.

다시 실행하기

Node.js 24 이상과 pnpm 11 이상을 사용합니다. 소스를 동기화되지 않는 로컬 폴더에 두고 .env.example을 참고해 로컬 환경변수를 설정하세요. 비밀값을 Git이나 공유 폴더에 저장하지 마세요.

pnpm install
pnpm db:migrate
pnpm dev
# http://127.0.0.1:3000
pnpm test
pnpm typecheck
pnpm build

전체 설정은 README.md를 참고하세요. 이 문서는 기준 커밋의 스냅샷이므로 코드 변경에 따라 갱신해야 합니다.

확인 경계: 비공개 저장소 분석·새로고침 후 결과 유지는 사용자 확인. Vercel 배포 후 일일 예약 실행은 아직 미관측. 모든 SDK와 동적 주소를 탐지하거나 API 정상 동작을 보장하지 않습니다.
